# MCP portal profiles

Install Doctor provisions the secret-free portal matrix at
`~/.config/mcp-portals/endpoints.json`. The five northbound profiles are:

| Profile | Endpoint | Authentication |
|---|---|---|
| `primary` | `https://mcp.megabyte.space/mcp` | Browser OAuth plus device posture |
| `automation` | `https://automation.mcp.megabyte.space/mcp` | Cloudflare Access service token |
| `sandbox` | `https://sandbox.mcp.megabyte.space/mcp` | Browser OAuth plus device posture |
| `ops` | `https://ops.mcp.megabyte.space/mcp` | Browser OAuth/posture with upstream step-up controls |
| `canary` | `https://canary.mcp.megabyte.space/mcp` | Browser OAuth plus device posture |

Inspect a profile without resolving credentials:

```sh
mcp-portal-profile.mjs list
mcp-portal-profile.mjs url canary
```

Run an automation adapter with runtime-only credentials:

```sh
mcp-portal-profile.mjs exec automation -- your-mcp-adapter
```

The helper resolves `CF_ACCESS_MCP_AUTOMATION_CLIENT_ID` and
`CF_ACCESS_MCP_AUTOMATION_CLIENT_SECRET` through `get-secret` immediately
before starting the adapter. It exposes the endpoint and credentials to that
child as `MCP_PORTAL_URL`, `MCP_PORTAL_CF_ACCESS_CLIENT_ID`, and
`MCP_PORTAL_CF_ACCESS_CLIENT_SECRET`; it does not print or write their values.
The adapter maps the latter two variables to Cloudflare's
`CF-Access-Client-Id` and `CF-Access-Client-Secret` HTTP headers.

These reference names are checked against the pinned canonical automation
manifest so the helper cannot silently drift to an absent alias.

CUA Driver, BrowserMCP, filesystem, shell, and other host-control tools remain
local and session-scoped. This descriptor does not replace their client
registrations or alter the local MCP singleton broker.

## Canonical host-manifest installation

The authoritative host assignments are generated by
`heymegabyte/mcp.megabyte.space`. Install Doctor pins an exact canonical Git
revision and every consumed artifact digest in
`config/mcp-portals/canonical-pin.json`. Exact generated artifacts are vendored
under `config/mcp-portals/canonical-profiles/` so provisioning does not depend
on anonymous access to the private canonical repository. The consumer verifies
those pins before it prepares any local output:

```sh
# Metadata-only plan; no files change.
node scripts/mcp-host-manifest-consumer.mjs plan \
  --host-class macos-workstation \
  --client-config "$HOME/.config/example-mcp/client.json"

# Explicit transactional installation with a protected rollback receipt.
node scripts/mcp-host-manifest-consumer.mjs apply \
  --host-class macos-workstation \
  --client-config "$HOME/.config/example-mcp/client.json" \
  --receipt "$HOME/.local/state/install.doctor/mcp-profile-rollback.json"

# Restores exact predecessors only when installed outputs have not drifted.
node scripts/mcp-host-manifest-consumer.mjs rollback \
  --receipt "$HOME/.local/state/install.doctor/mcp-profile-rollback.json"
```

Use `ubuntu-runner` for the Ubuntu host pair. Each installation consumes both
the host's human and automation manifests. Automation credential material is
never embedded: the installed descriptor and optional JSON client entry carry
only the canonical Infisical runtime secret references and header bindings.

Unknown descriptor fields, profiles, and MCP client registrations are
preserved. A pre-existing `megabyte-*` name not marked as owned by the
canonical repository is a collision and aborts before any write. Apply creates
mode-`0600` predecessor snapshots, uses same-directory atomic replacement, and
emits a metadata-only receipt. Rollback refuses to overwrite operator changes
made after installation.

## OpenClaw automation registration

OpenClaw uses its native `mcp.servers` registry. The Install Doctor adapter
adds only `megabyte-automation`, preserves unrelated OpenClaw settings and
servers, and writes the two Cloudflare headers as environment placeholders.
Resolved values never enter `openclaw.json`, command arguments, output, the
receipt, or its predecessor snapshot.

```sh
# Read-only: inspect identity, output digest, and preservation counts.
node scripts/openclaw-mcp-automation-adapter.mjs plan \
  --host-class ubuntu-runner \
  --config "$HOME/.openclaw/openclaw.json"

# Explicit install after reviewing the plan. This does not resolve secrets.
node scripts/openclaw-mcp-automation-adapter.mjs apply \
  --host-class ubuntu-runner \
  --config "$HOME/.openclaw/openclaw.json" \
  --receipt "$HOME/.local/state/install.doctor/openclaw-mcp-automation.json"

# The existing Gateway command must be preserved after `--`; only its launch
# gains the runtime-only environment required by the two header placeholders.
node scripts/openclaw-mcp-automation-adapter.mjs exec \
  --host-class ubuntu-runner \
  --allowed-executable /absolute/path/to/openclaw \
  -- /absolute/path/to/openclaw gateway

node scripts/openclaw-mcp-automation-adapter.mjs rollback \
  --receipt "$HOME/.local/state/install.doctor/openclaw-mcp-automation.json"
```

Use `macos-workstation` on macOS. `exec` accepts only an executable whose
path exactly matches `--allowed-executable`, invokes no shell, resolves exactly
`CF_ACCESS_MCP_AUTOMATION_CLIENT_ID` and
`CF_ACCESS_MCP_AUTOMATION_CLIENT_SECRET` through `get-secret`, and refuses to
start OpenClaw when either value is unavailable.

Do not replace a live service command from a generic example. First capture the
active unit and OpenClaw config path, run the metadata-only plan, and verify its
preservation counts. A later operator-controlled cutover must wrap the exact
existing command and retain all arguments, then validate OpenClaw config,
Gateway health, MCP initialization and tool listing, wrong-endpoint denial,
mode `0600`, and rollback. This repository change intentionally performs no
live Ubuntu apply or restart.

The registration shape follows OpenClaw's upstream
[native MCP registry](https://github.com/openclaw/openclaw/blob/main/docs/tools/mcp.md)
and its documented
[HTTP header environment substitution](https://github.com/openclaw/openclaw/blob/main/docs/cli/mcp/transports.md).

### Ubuntu systemd-user cutover

The deployed Ubuntu Gateway may invoke Node and OpenClaw's `dist` entrypoint
directly. Do not rewrite that command to a guessed `openclaw` shim. Review the
active `ExecStart`, encode its exact argv as JSON, and run a metadata-only plan:

```sh
GATEWAY_ARGV='["/absolute/node","/absolute/openclaw/dist/index.js","gateway","--port","18789"]'
node scripts/openclaw-systemd-reconciler.mjs plan \
  --gateway-argv-json "$GATEWAY_ARGV"
```

Plan prints `gatewayArgvDigest`, the preserved `gatewayPort`, and the current
`unitExecStartDigest`, but not the argv itself. After coordinator review, apply
must use that exact digest so a unit change between plan and apply fails closed:

```sh
node scripts/openclaw-systemd-reconciler.mjs apply \
  --gateway-argv-json "$GATEWAY_ARGV" \
  --expected-exec-start-digest 'sha256:<from-plan>' \
  --receipt "$HOME/.local/state/install.doctor/openclaw-systemd-mcp.json"
```

The reconciler copies the adapter and all pinned runtime inputs to stable
user-local mode-`0600` paths, atomically installs only an `ExecStart` drop-in,
runs `systemd-analyze --user verify`, reloads the user manager, restarts the
Gateway, and proves it active. A failed lifecycle gate restores all files and
attempts to restart the predecessor. Explicit rollback also reloads, restarts,
and checks the restored service. Repository delivery does not run these live
commands; the coordinator owns the reviewed Ubuntu plan and apply.
