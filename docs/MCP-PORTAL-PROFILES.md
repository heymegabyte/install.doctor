# MCP portal profiles

Install Doctor provisions the secret-free portal matrix at
`~/.config/mcp-portals/endpoints.json`. The five northbound profiles are:

| Profile | Endpoint | Authentication |
|---|---|---|
| `primary` | `https://mcp.megabyte.space/mcp` | Browser OAuth plus device posture |
| `automation` | `https://automation.mcp.megabyte.space/mcp` | Cloudflare Access service token |
| `sandbox` | `https://sandbox.mcp.megabyte.space/mcp` | Browser OAuth plus device posture |
| `ops` | `https://ops.mcp.megabyte.space/mcp` | Browser OAuth/posture with upstream step-up controls |
| `canary` | `https://canary.mcp.megabyte.space/mcp` | Browser OAuth plus device posture |

Inspect a profile without resolving credentials:

```sh
mcp-portal-profile.mjs list
mcp-portal-profile.mjs url canary
```

Run an automation adapter with runtime-only credentials:

```sh
mcp-portal-profile.mjs exec automation -- your-mcp-adapter
```

The helper resolves `MCP_AUTOMATION_CF_ACCESS_CLIENT_ID` and
`MCP_AUTOMATION_CF_ACCESS_CLIENT_SECRET` through `get-secret` immediately
before starting the adapter. It exposes the endpoint and credentials to that
child as `MCP_PORTAL_URL`, `MCP_PORTAL_CF_ACCESS_CLIENT_ID`, and
`MCP_PORTAL_CF_ACCESS_CLIENT_SECRET`; it does not print or write their values.
The adapter maps the latter two variables to Cloudflare's
`CF-Access-Client-Id` and `CF-Access-Client-Secret` HTTP headers.

CUA Driver, BrowserMCP, filesystem, shell, and other host-control tools remain
local and session-scoped. This descriptor does not replace their client
registrations or alter the local MCP singleton broker.

## Canonical host-manifest installation

The authoritative host assignments are generated by
`heymegabyte/mcp.megabyte.space`. Install Doctor pins an exact canonical Git
revision and every consumed artifact digest in
`config/mcp-portals/canonical-pin.json`. Exact generated artifacts are vendored
under `config/mcp-portals/canonical-profiles/` so provisioning does not depend
on anonymous access to the private canonical repository. The consumer verifies
those pins before it prepares any local output:

```sh
# Metadata-only plan; no files change.
node scripts/mcp-host-manifest-consumer.mjs plan \
  --host-class macos-workstation \
  --client-config "$HOME/.config/example-mcp/client.json"

# Explicit transactional installation with a protected rollback receipt.
node scripts/mcp-host-manifest-consumer.mjs apply \
  --host-class macos-workstation \
  --client-config "$HOME/.config/example-mcp/client.json" \
  --receipt "$HOME/.local/state/install.doctor/mcp-profile-rollback.json"

# Restores exact predecessors only when installed outputs have not drifted.
node scripts/mcp-host-manifest-consumer.mjs rollback \
  --receipt "$HOME/.local/state/install.doctor/mcp-profile-rollback.json"
```

Use `ubuntu-runner` for the Ubuntu host pair. Each installation consumes both
the host's human and automation manifests. Automation credential material is
never embedded: the installed descriptor and optional JSON client entry carry
only the canonical Infisical runtime secret references and header bindings.

Unknown descriptor fields, profiles, and MCP client registrations are
preserved. A pre-existing `megabyte-*` name not marked as owned by the
canonical repository is a collision and aborts before any write. Apply creates
mode-`0600` predecessor snapshots, uses same-directory atomic replacement, and
emits a metadata-only receipt. Rollback refuses to overwrite operator changes
made after installation.
