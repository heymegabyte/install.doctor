# Design: Cross-Platform Legacy Site Build & Vite/`@theme.tools` Migration

> **Architect:** antigravity
> **Architect Role:** assigned

## Context

`site/` contains a Stencil v3 marketing frontend (`site/stencil.config.ts`) and an embedded Docusaurus v2 documentation workspace (`site/docs/`). Two existing CI workflows (`site-preview.yml` and manual-only `site-deploy.yml`) build the combined artifact on `ubuntu-latest` with SHA-verified `shdoc` and `task` binaries. Meanwhile, Windows contributors running `npm install --force && npm run build` or `npm start` on Node 22 fail immediately (`install.doctor#172`).

Repository guardrails impose strict constraints on any fix:
- `scripts/test-inherited-capacitor-site-docs.sh` forbids `site/readme.md` (which collides with `site/README.md` on case-insensitive NTFS/APFS filesystems).
- `scripts/test-site-doc-mirror-generation.sh` and `scripts/test-landing-page.sh` directly exercise `site/docs/scripts/markdown.sh`.
- `scripts/test-workflow-action-pins.sh` requires full 40-hex commit SHAs on every external GitHub Action.
- `scripts/test-site-deploy-workflow.sh` requires `site-deploy.yml` to remain `workflow_dispatch`-only.

## Architecture & Decisions

### 1. Environment-Driven Global Stylesheet Selection (Zero Symlink Dependency)

Instead of mutating `site/src/global/style.scss` via `rm` and `ln -s`, `site/stencil.config.ts` resolves `globalStyle` at config load time:
- `SITE_NOSCRIPT === '1'` -> `./src/global/style-offline.scss`
- default -> `./src/global/style-default.scss`

`site/scripts/build-noscript.mjs` invokes `@stencil/core/bin/stencil` via `process.execPath` with `SITE_NOSCRIPT=1` and copies `www/build/site.css` to `src/site-noscript.css` using `fs.copyFileSync`. The tracked `style.scss` file is never read or mutated during builds, eliminating `core.symlinks=false` failures on Windows.

### 2. Conditional `../docs/build` Static Copy

Stencil resolves `{ src: '../docs/build', dest: 'docs' }` relative to `site/src/` (i.e., `site/docs/build`). Guarding that copy entry with `existsSync(join(__dirname, 'docs', 'build'))` allows `npm run build` and `npm start` to succeed standalone on a fresh clone while preserving full `/docs` static bundling during `npm run build:prod` (where `build:docs` runs first).

### 3. Dual-Mode Cross-Platform Docs Prebuild (`generate-plugin-docs.mjs` + `prebuild.mjs`)

To preserve 100% parity with Linux release builds while unblocking Windows and minimal developer workstations:
- On non-Windows hosts where `bash`, `rsync`, `shdoc`, and `task` are all present on `PATH` (and `FORCE_PORTABLE_DOCS_MIRROR !== '1'`), `generate-plugin-docs.mjs` delegates directly to `bash scripts/markdown.sh`.
- On Windows (`process.platform === 'win32'`) or hosts missing `rsync`/`shdoc`/`task`, `generate-plugin-docs.mjs` executes a pure Node `fs` pipeline that cleans stale non-image files, mirrors canonical `docs/` (honoring the exact exclusion set from `markdown.sh`), and generates MDX-safe reference pages for `home/**/*.sh.tmpl`, `scripts/*.sh`, and `home/dot_config/task/Taskfile.yml` so every autogenerated sidebar in `site/docs/sidebars.js` resolves cleanly.

### 4. Phase 2 Target Architecture (Vite + React 19 + `@theme.tools`)

Full stack modernization is intentionally decoupled from the cross-platform bugfix so `#172` ships safely without altering Firebase hosting cutover authority:
- Target runtime: Cloudflare Workers + Hono static/SSR edge worker serving dark-first (`#060610` / `#00E5FF`) React 19 + Vite routes built on `@theme.tools/ui`, `@theme.tools/themes`, `@theme.tools/blog`, and `@theme.tools/seo-geo`.
- Cutover gate: URL parity map covering legacy prerendered marketing routes and `/docs/**` slugs, 6-breakpoint Playwright E2E + axe-core WCAG 2.2 AA gate, and explicit release sign-off before retiring `site-deploy.yml`.
